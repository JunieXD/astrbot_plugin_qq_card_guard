# QQ 群名片规范

[![Tests](https://github.com/JunieXD/astrbot_plugin_qq_card_guard/actions/workflows/test.yml/badge.svg)](https://github.com/JunieXD/astrbot_plugin_qq_card_guard/actions/workflows/test.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

给 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 使用的 QQ 群名片管理插件。成员发言后，按你设置的正则检查**群名片**，提醒未按格式改名的人；可选择逐轮禁言。改好后自动核验，先解除能够确认属于本插件的禁言，再撤回对应提醒。

每群独立配置，无需 LLM。**默认关闭发言检查，新添加的群默认“仅观察”。**

## 能做什么

- 只检查发言的人，不定期扫描全群，也不处罚单纯潜水的人。
- 每群设置名片正则、格式说明、示例、提醒内容和禁言阶梯。
- 群主、管理员、机器人自身始终豁免；可按群等级、QQ 等级、群专属头衔或名单豁免。
- 连发消息合并为一轮；到期后再次发言且仍不合规，才进入下一轮。
- 合规默认免查60分钟，豁免免查10分钟；名片或规则变化后重新核验，连续发言不会延长缓存。
- 群名片通知 + 分阶段补查，仍在禁言期的成员优先核验；重复发言与补查合并，减少查询。
- 提醒、禁言、解禁、撤回分别随机等待；账号串行操作，配合频率上限、恢复冷却和读取预算。
- SQLite 保存轮次、消息 ID、操作意图和额度；超时或重载后不盲目重发。
- 私聊命令测试正则、查看原因、设置豁免、暂停及人工接手。

## 安装与首次使用

需要 Python 3.10+、AstrBot `>=4.26.2,<5`，通过 `aiocqhttp` 接入 NapCat。接口适配依据为 **NapCat 4.18.19**；其他版本需提供同样的接口和字段，缺少关键资料时会暂缓。机器人需要群管理权限。

1. 在 AstrBot 插件页通过仓库地址安装：

   ```text
   https://github.com/JunieXD/astrbot_plugin_qq_card_guard
   ```

2. 打开插件配置，在「要管理的群」添加一条，填群号、名片正则、格式说明和正确示例。其他设置可先保留默认。
3. 私聊机器人测试几种名片，再打开「启用发言检查」，保持「仅观察」查看判断日志：

   ```text
   /名片规范 测试 123456789 大三-某某大学
   /名片规范 检查 123456789 987654321
   /名片规范 状态 123456789
   ```

4. 确认符合群规后，将这个群改为「只提醒」或「提醒并禁言」，保存配置。建议先在测试群确认成员实际可以修改自己的群名片，包括被禁言时。

仓库中的群号、QQ 号均为占位示例。安装依赖由 `requirements.txt` 提供，主要使用支持匹配超时的 `regex`。

## 最常用的设置

| 设置 | 怎么填 |
| --- | --- |
| 运行方式 | **仅观察**：只记录判断；**只提醒**：提醒并跟进改名；**提醒并禁言**：按阶梯增加禁言 |
| 群名片正则 | 完整匹配实际群名片；空名片不合格，不以 QQ 昵称代替 |
| 格式说明 / 正确示例 | 直接出现在提醒里，写成员看得懂的内容 |
| 群等级达到多少就豁免 | `0` 不启用；`10` 表示群等级 ≥10 的人豁免 |
| 豁免有群专属头衔的人 | 默认打开；指群主授予的专属头衔 |
| 始终豁免的 QQ 号 | 每项一个 QQ，也可用私聊命令临时豁免 |
| 每轮违规禁言几分钟 | 按顺序填 `0`、`10`、`60`、`360`；`0` 只提醒；超过列表长度重复最后一档 |
| 首次提醒宽限 | 默认至少 10 分钟后才可能进入下一轮 |
| 无新违规重置天数 | 默认 7 天；改好后不会立刻抹掉近期轮次 |

「更多设置」包括新成员只提醒期、同成员提醒间隔、个人禁言上限、QQ 等级豁免、忽略大小写、自动解禁/撤回开关和多账号绑定。表单均带说明；完整字段和边界见 [配置参考](docs/configuration.md)。

### 一个正则例子

要求“年级-学校”，年级允许“大一～大五、研一～研三”，学校字段为 2～40 个非空白字符：

```regex
(?:大[一二三四五]|研[一二三])-\S{2,40}
```

它检查**格式**，不会判断学校是否真实，也不判断 985、211 或双一流。允许数字年级可以自行改成例如 `(?:20\d{2}|大[一二三四五]|研[一二三])-\S{2,40}`。默认忽略名片两端空白，内部空白由你的正则决定。

提醒会自动在开头 @ 当事人。模板支持 `{格式说明}`、`{正确示例}`、`{违规轮次}`、`{禁言分钟}`、`{群号}`、`{QQ号}`。需要每轮不同的语气时，可填写「每轮单独的提醒内容」，未填写的轮次使用通用提醒。

### 反复不改名时怎样处理

默认流程如下，全部可通过表单调整：

| 轮次 | 行为 |
| --- | --- |
| 第 1 轮 | 提醒，不禁言；至少留 10 分钟宽限 |
| 第 2 轮 | 再提醒，之后禁言 10 分钟 |
| 第 3 轮 | 再提醒，之后禁言 60 分钟 |
| 第 4 轮及以后 | 再提醒，之后最多禁言 360 分钟 |

**禁言到期不会自动续禁。**需要在宽限、提醒间隔和本轮禁言时间都结束后，再收到该成员的新发言，才可能进入下一轮。已改名又改回，也遵守提醒间隔，不会立刻连罚。默认每个人最近 24 小时最多禁言 3 次，到上限时本轮仅提醒，不会排队补罚。插件不自动踢人。

默认入群前 10 分钟只提醒；已被禁言的人不覆盖或延长其现有禁言。管理员中途解除或修改禁言后，本轮不会重新禁言。

## 私聊管理命令

目标群当前的**群主或管理员**可使用，AstrBot 的全局管理员身份不能代替目标群管理权限。别名为 `/qcard`；命令回复保持简洁，不调用 LLM。每人每群命令至少间隔 10 秒。

| 命令 | 用途 |
| --- | --- |
| `/名片规范` | 帮助 |
| `/名片规范 状态 群号` | 开关、模式、待处理、查询额度、缓存命中、暂缓与过时跳过统计 |
| `/名片规范 测试 群号 名片` | 测试正则，不发送群提醒或处罚 |
| `/名片规范 检查 群号 QQ号` | 查看成员当前名片、豁免/不合规原因和禁言截止 |
| `/名片规范 待处理 群号 [页码]` | 待处理事项；需要人工核对的记录优先显示 |
| `/名片规范 历史 群号 [页码]` | 历史记录，每页 10 条 |
| `/名片规范 豁免 群号 QQ号 [天数]` | 默认永久，`0` 也表示永久 |
| `/名片规范 取消豁免 群号 QQ号` | 取消命令设置的豁免；不改变配置里的名单 |
| `/名片规范 暂停 群号` | 暂停新增提醒/禁言，继续已有事项的解禁和撤回核验 |
| `/名片规范 恢复 群号` | 解除人工暂停，经过恢复冷却后继续 |
| `/名片规范 核对 群号 记录号` | 查看结果不明事项和成员当前资料 |
| `/名片规范 接手 群号 记录号` | 交由管理员人工处理，并暂停这个群新增处理 |

“接手”不声称已撤回或解禁，也不会再向 QQ 提交该事项的操作。请在 QQ 中核对实际状态，手动处理完后使用“恢复”。出现不明的提醒/禁言请求会暂停这个账号的新处罚；同账号其他群的管理员也不能替来源群解除这项暂停。

## 节奏与平台限制

默认提醒前等待 **8～20 秒**，提醒成功到禁言再等 **3～8 秒**；发现合规到解禁 **1～3 秒**，撤回前 **2～6 秒**，同账号写操作之间至少 **3～8 秒**。资料读取还有独立间隔，队列、额度和重新核验可能增加实际等待。这些范围都可配置。

每个机器人默认最近60分钟最多600次资料查询，普通检查使用至65%，普通补查至85%，余量用于禁言中成员和恢复操作；配置页可调。缓存只用于跳过重复检查，不能代替提醒、禁言、解禁前的实时核验。超过5分钟的旧发言不会延迟处罚，状态命令会显示跳过统计。

每群每小时默认最多 10 次提醒；每个机器人每小时最多 30 次提醒、最近 24 小时最多 30 次禁言。失败或结果不明的已提交请求也占额度。随机等待能减少集中操作和固定间隔，**不能保证避免 QQ 风控**。

请了解以下实际限制：

- NapCat 的 `group_card` 通知并非可靠的即时改名推送。因此插件只对待处理成员补查，默认前3分钟每30～60秒一次，随后依次放慢到1～2、3～5、10～20和30～60分钟；仍在本插件禁言期内的成员按20～40秒优先补查，读取预算不足会进一步推迟，**不能保证秒级解禁**。
- 解禁要求禁言请求成功、收到匹配的本账号禁言通知，且当前截止时间匹配。通知缺失、结果不明、其他管理员介入、离群重进时不猜测归属。同账号再次禁言也会使原归属失效；升级前缺少通知序号的旧禁言需人工核对。使用同一个 QQ 的其他插件也可能禁言；无法区分的情况交由人工。
- QQ/NapCat 没有“仅当原禁言仍属于此请求时才解禁”的原子接口。插件尽量缩小核验与提交之间的窗口，但不能消除接口缓存、漏通知及外部操作竞争。
- 撤回前核对群、发送者、消息 ID、时间和提醒内容。NapCat 重启、缓存淘汰或 QQ 撤回限制可能导致旧消息不可撤回；这不会阻塞已确认属于本插件的解禁。
- NapCat 的 `card_changeable` 不能可靠证明该群允许成员自己改名，必须在实际群中确认；否则先使用“只提醒”并由管理员处理。
- 资料缺失或正则超时会暂缓，不会把未知成员当成违规者。正则语法错误只停用对应群。
- 总开关关闭仍保留已有事项的跟进。**卸载、停用插件、停止 AstrBot 或不可写的审计存储会停止自动恢复**，未解除的禁言等待自然到期或由管理员处理。切换负责的机器人 QQ 前，应先完成旧账号的待处理事项。

兼容同一 AstrBot 进程内现有的 `_qq_automation_guard_v1` 共享队列（如 QQ 加群审核插件提供的队列），以平台 ID 协同间隔。没有该队列也可独立运行；不能统一约束不参与协调的插件、别的进程或人工操作。

## 日志和数据

位于 AstrBot 的 `data/plugin_data/astrbot_plugin_qq_card_guard/`：

| 文件 | 内容 |
| --- | --- |
| `state.sqlite3`（及 WAL/SHM） | 轮次、待处理事项、操作记录、额度和人工豁免 |
| `logs/guard.log` | 调度、接口、异常和操作结果 |
| `logs/decisions.log` | 名片、保护条件与判断原因 |

`guard.log` 还记录免查命中/失效原因、补查阶段及下次时间、限流用量/门槛/恢复时间、过时发言跳过原因。`decisions.log` 使用 `member_level` 保存群等级，`level` 始终表示日志严重程度。

同一份免查缓存失效只记录一次，重新核验生成缓存后才开始下一轮。正常操作间隔、启动缓冲和管理员恢复后的等待使用 `INFO`，记录具体原因及恢复时间；连接恢复和读取额度不足仍使用 `WARNING`，多个等待条件会一并保留。

NapCat 明确返回的业务失败会记录接口名、返回码和脱敏后的错误信息，不会仅因此清空连接缓存或触发全局连接冷却。例如旧提醒返回“消息不存在”时，只将该条撤回转交人工核对，不推断已撤回，也不重复尝试。真正的超时、断线或无法分类的异常仍触发保护；已经提交的写操作若结果不明，仍按原规则停止自动重试。

两个日志独立按大小轮转：**每份 20 MiB，保留当前文件 + 7 份归档**，正常合计约 320 MiB 上限，单条完整记录可能略超边界；不按日期删除。每行完整 JSON，多行错误和异常链不会被截断，凭证与 URL 会脱敏。

不记录普通群聊正文，但会保存群号、QQ 号、群名片、判断和处罚记录；这些属于管理数据，请勿直接提交公开仓库。SQLite 保留审计历史，不按天删记录；仅事件去重缓存保留 48 小时。达到 512 MiB 或剩余磁盘不足 256 MiB 时停止自动操作。需要归档时应先完成待处理事项，再停用插件并处理完整数据目录，不能在运行中只删除主数据库。
