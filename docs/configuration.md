# 配置参考

日常只需添加群，填写正则、说明和示例，再选择运行方式。全部设置都可以在 AstrBot 插件配置页修改。

## 全局开关

`enabled` 默认 `false`，只控制新增发言检查与处罚；已有事项的合规核验仍继续。停用或卸载插件会停止所有任务。

## 每个群

位于 `groups`。最多 30 个群，同一群不能重复添加。错误配置只停用对应群，执行节奏等全局配置错误会阻止启动。

| 字段 | 界面名称 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `group_id` | QQ群号 | `""` |  |
| `enabled` | 管理这个群 | `true` | 关闭仅停止新增提醒和禁言；已有事项继续核验。 |
| `mode` | 运行方式 | `"仅观察"` | 先观察日志与测试正则，确认后切换。只提醒永不新增禁言；已有禁言仍按归属核验。 |
| `pattern` | 群名片正则 | `"(?:大[一二三四五]\|研[一二三])-\\S{2,40}"` | 对完整群名片匹配，空名片不合格，不使用QQ昵称代替。可私聊 /名片规范 测试 群号 名片。 |
| `format_help` | 告诉成员应使用的格式 | `"年级-学校"` |  |
| `example` | 正确示例 | `"大三-某某大学"` |  |
| `protect_level` | 群等级达到多少就豁免 | `0` | 0表示不按等级豁免；设为10则≥10豁免，资料不明时暂缓。群主、管理员和机器人自身始终豁免。 |
| `compliant_cache_minutes` | 合规成员免查几分钟 | `60` | 0～1440；0关闭。以实际核验时间计时，发言不续期；已有事项继续跟进。 |
| `exempt_cache_minutes` | 豁免成员免查几分钟 | `10` | 0～1440；临时豁免到期会提前失效。 |
| `protect_title` | 豁免有群专属头衔的人 | `true` |  |
| `exempt_users` | 始终豁免的QQ号 | `[]` | 每项一个QQ号；也可以通过私聊命令临时或永久豁免。 |
| `reminder` | 提醒内容 | `"请将群名片改为：{格式说明}。例如：{正确示例}。改好后会自动核验并撤回提醒；如有本插件设置的禁言，会一并核验解除。"` | 自动在前面@成员。可用：{格式说明}、{正确示例}、{违规轮次}、{禁言分钟}、{群号}、{QQ号}。 |
| `stage_minutes` | 每轮违规禁言几分钟 | `["0", "10", "60", "360"]` | 按第1、2、3…轮排列；0为只提醒，超过项数重复最后一档。每项0～1440分钟，最多8档；仅在“提醒并禁言”生效。到期后必须有新发言才会进入下一轮。 |
| `first_grace_minutes` | 首次提醒后至少等几分钟才可再次提醒 | `10` | 1～1440；与禁言到期时间和提醒间隔取较晚值。 |
| `reset_days` | 多少天没有新违规轮次就从第一轮重新开始 | `7` | 1～365天。改好名片会结束当前事项，但不会立刻清零近期违规轮次。 |
| `advanced.newcomer_minutes` | 入群多久内只提醒，不新增禁言（分钟） | `10` | 0～10080；0关闭新成员保护。 |
| `advanced.repeat_minutes` | 同一个人两次提醒至少间隔几分钟 | `5` | 1～1440；连发消息只计一轮。 |
| `advanced.daily_mutes` | 每个人最近24小时最多禁言几次 | `3` | 1～10；达到上限，本轮仍可提醒但不会延迟补罚。 |
| `advanced.protect_qq_level` | QQ等级达到多少就豁免 | `0` | 0关闭。群等级和QQ等级不同；开启后QQ等级缺失或为0会暂缓。 |
| `advanced.strip_spaces` | 匹配前忽略名片两端空白 | `true` |  |
| `advanced.ignore_case` | 匹配时忽略英文字母大小写 | `false` |  |
| `advanced.recall_on_compliance` | 合规或获得豁免后撤回提醒 | `true` |  |
| `advanced.unmute_on_compliance` | 合规或获得豁免后解除本插件禁言 | `true` | 只解除有归属证据、仍然有效的禁言；管理员中途修改或归属不明交人工。 |
| `advanced.bot_qq` | 负责这个群的机器人QQ（通常留空） | `""` | 只接入一个QQ时自动识别。多QQ接入时请填写，每群只由一个QQ负责。 |
| `stage_reminders` | 每轮单独的提醒内容（可不填） | `[]` | 与禁言阶梯逐项对应。未填写的轮次使用上面的通用提醒，超过阶梯后使用最后一档；支持同样的占位符。 |

处理阶梯最多 8 档，每档 0～1440 分钟，可设置成相同、递增或自行指定的顺序；`只提醒` 模式会忽略所有禁言分钟。`stage_reminders` 的长度不能超过阶梯长度，未提供的项或空字符串使用通用提醒。

群号和QQ号接受字符串或整数，范围 10000～9999999999999。豁免名单最多 2000 项；正则最长 2000 字符、匹配名片最长 512 字符，单次匹配超时 50 毫秒。正则语法错误或匹配超时不会触发处罚。

通用提醒不能是空白，展开占位符后每条提醒最多2000字。

名片资料缺失、身份/入群时间不明、启用的保护字段缺失或禁言状态不明时，先等待补查。群等级为 0 有效；QQ 等级 0 视作未知。

## 执行节奏

位于 `pace`，所有群共用。账号额度仅统计本插件，不能统计其他插件、客户端或人工操作。

| 字段 | 界面名称 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `notify_min` | 提醒前等待最短秒数 | `8` | 到时会重新核验，期间改好就取消。 |
| `notify_max` | 提醒前等待最长秒数 | `20` | 不能小于对应最短值；每次独立抽取随机值。 |
| `ban_min` | 提醒成功后到禁言之间等待最短秒数 | `3` | 期间再次核验；提醒失败不会禁言。 |
| `ban_max` | 提醒成功后到禁言之间等待最长秒数 | `8` | 不能小于对应最短值；每次独立抽取随机值。 |
| `unmute_min` | 发现合规后到解禁之间等待最短秒数 | `1` | 优先处理解禁，之后另行撤回。 |
| `unmute_max` | 发现合规后到解禁之间等待最长秒数 | `3` | 不能小于对应最短值；每次独立抽取随机值。 |
| `recall_min` | 撤回提醒前等待最短秒数 | `2` | 每条提醒分别等待并核对身份。 |
| `recall_max` | 撤回提醒前等待最长秒数 | `6` | 不能小于对应最短值；每次独立抽取随机值。 |
| `gap_min` | 同一账号两次写操作之间间隔最短秒数 | `3` | 所有群共用，最短至少1秒；兼容已有QQ自动化共享队列时可能额外等待。 |
| `gap_max` | 同一账号两次写操作之间间隔最长秒数 | `8` | 不能小于对应最短值；每次独立抽取随机值。 |
| `poll_min` | 提醒初期补查最短秒数 | `30` | 进入首个后续阶梯前使用；旧配置中的自定义值保留。 |
| `poll_max` | 提醒初期补查最长秒数 | `60` | 不能小于最短值。 |
| `muted_poll_min` | 禁言期间补查最短秒数 | `20` | 15～600；仍在本插件禁言期时使用优先读取额度。 |
| `muted_poll_max` | 禁言期间补查最长秒数 | `40` | 到期后回到普通阶梯。 |
| `startup_min` | 普通启动或重载缓冲最短秒数 | `30` | 只影响新增处理；两项都填0可关闭这项缓冲。 |
| `startup_max` | 普通启动或重载缓冲最长秒数 | `90` | 不能小于对应最短值；每次独立抽取随机值。 |
| `recovery_min` | 异常恢复冷却最短秒数 | `300` | 连接异常或执行“恢复”后使用；已排定的冷却不会因调小配置而缩短。 |
| `recovery_max` | 异常恢复冷却最长秒数 | `900` | 不能小于对应最短值；每次独立抽取随机值。 |
| `group_hourly_reminders` | 每群最近1小时最多提醒几次 | `10` | 1～100；已提交但结果不明的请求也占额度。 |
| `account_hourly_reminders` | 每个QQ最近1小时最多提醒几次 | `30` | 1～300；本插件所有群合计。 |
| `account_daily_mutes` | 每个QQ最近24小时最多禁言几次 | `30` | 1～100；本插件所有群合计。解禁不占禁言额度。 |
| `reads_per_hour` | 每个QQ每小时资料读取预算 | `600` | 60～1200；为待处理核验和解禁预留额度。群多、待处理人多时，发现改名可能需要更久。 |
| `max_pending` | 每个QQ最多同时跟进多少人 | `30` | 1～100；按群/成员去重计数，达到上限优先完成已有事项。 |

通知、禁言、解禁、撤回、普通启动延迟为 0～600 秒；账号间隔最短至少 1 秒。补查为 30～3600 秒，恢复冷却为 1～3600 秒。每对最小值均不得大于最大值。

最近 1 小时 / 24 小时为滚动窗口，不在午夜清零。提高提醒或禁言额度不会自动提高读取预算；资料读取受限时保留事项，待预算恢复后再检查。读取预算的前 65% 可用于新违规核验，85% 以内可用于一般待处理补查，剩余部分留给禁言中成员、解禁/撤回及管理核对。普通额度用完不等于所有额度用完；恢复时间按实际需要释放的查询数量计算。改变预算会重新调度旧限流等待，但不会跳过额度核验。

读取 API 默认另有 1.5～3 秒间隔。随机等待之后仍会执行资料核验，因此表单的等待时间不是对实际完成时间的保证。后续间隔由顶层 `followup_steps` 控制，1～8档，起始分钟必须递增，间隔逐档不缩短：

| 提醒成功后多少分钟 | 间隔最短秒数 | 间隔最长秒数 |
| --- | --- | --- |
| 3 | 60 | 120 |
| 10 | 180 | 300 |
| 30 | 600 | 1200 |
| 120 | 1800 | 3600 |

每行字段是 `after_minutes`（1～43200）、`minimum` / `maximum`（30～86400）。收到名片变化会提前核验，但不重置提醒时间或绕过限流；没有变化的连发合并进已有跟进。首次补查沿用 `poll_min/max`，禁言期间则使用独立间隔。

普通重载会取消未提交的旧处罚并重新缓冲；已有恢复冷却和写操作间隔保留。已有冷却与操作间隔不提前；调整查询预算会重新核对限流等待。缓存绑定连接会话，重载/重连后重新核验，不扫描全群。

## 推荐调整方式

- 先使用默认节奏，观察待处理数量和日志。群越多、待处理人越多，补查越可能延迟。
- 如果只希望提醒，选择“只提醒”，无需把每一档禁言时间改成零。
- 如果希望每次都只短暂禁言，设置单项阶梯，例如 `5`。
- 如果希望给两次改名机会，设置 `0、0、10、60`。
- 如果不希望自动撤回或解禁，在“更多设置”关闭相应开关；管理员仍可自行处理。
- 从启用改为停用前，先检查待处理事项。需要保留自动恢复时只关闭总检查开关，不卸载插件。

## 观察效果与排查

`/名片规范 状态 群号` 显示账号最近60分钟查询用量与普通门槛、可恢复时间，以及本群累计缓存命中、合并、暂缓、过时发言跳过次数（这些是次数，不是去重人数）。累计数据持久保存，自升级后开始记录。查询恢复时间是本次快照，其他任务继续消耗时可能变化。待处理列表会显示下一次处理时间。

合规和豁免缓存不会在继续发言时续期。改名提示、角色/入群变化、手动豁免变化、规则修改和连接变化会使缓存失效；如果平台既不提供改名通知，也不在新消息中提供变化的名片，则最迟需要等缓存到期后的新发言。临时豁免的缓存不超过豁免到期时间。处罚/解禁前的核验不使用这些缓存。

由于发言已过去5分钟、重载或额度限制，部分发言不会追加处罚；插件不会为了补历史队列突然集中提醒。对应跳过原因可在日志与状态统计追查。
